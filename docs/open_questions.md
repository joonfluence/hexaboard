# 미결 사항

아직 정하지 않은 항목이다. 결정되면 이 문서에서 지우고 [decision_log.md](decision_log.md)에 근거와 함께 옮긴다. 확정 항목은 여기에 적지 않는다.

## 진행 우선순위

기준: 첫 구현(첫 마이그레이션, 첫 API 계약)에 들어가서 나중에 바꾸기 비싼 것을 먼저 정한다. 항목의 상세는 아래 주제별 목록에 있다.

| 순위 | 항목 | 이유 |
|------|------|------|
| 구현 시 확정 | 마감일 표시 방식, 인라인 생성 위치, 상세 모달 저장 방식, 삭제 UI, 순서 키 길이 상한, dnd-kit 테스트 방식, Node 버전, 스키마·필터 파라미터 | 해당 코드를 쓰는 시점에 정한다 |
| 낮은 우선순위 | 응답 시간 목표, 다중 인스턴스 마이그레이션 경합 | 현재 규모에서 영향이 작다 |

## 데이터

- 현재 미결 항목 없음

## UI

- [ ] 마감일 표시 방식 (형식, 임박·초과 강조 여부)
- [ ] 인라인 티켓 생성 입력이 어느 컬럼 하단에 있는지 (생성은 항상 `TODO`인데 와이어프레임은 "컬럼 하단"이라고만 함)
- [ ] 카드 상세 모달의 저장 방식 (저장 버튼인지 자동 저장인지)
- [ ] 삭제 UI의 위치와 확인 절차

## 카드 이동·정렬

- [ ] 순서 키 길이 상한과 넘을 때의 처리 (구현 시 확정)

## 테스트

- [ ] 드래그(dnd-kit) 상호작용을 컴포넌트 테스트에서 다루는 방식

## 비기능

- [ ] 평상시 응답 시간 목표 (낮은 우선순위)

## 인프라

- [ ] 다중 인스턴스 동시 기동 시 마이그레이션 경합 (무료 플랜은 인스턴스 1개라 낮은 우선순위)

## 개발환경

- [ ] Node 정확한 버전 (구현 시점의 LTS)

## API

- [ ] 요청·응답 스키마 상세 (구현 시 OpenAPI로 확정)
- [ ] 필터 파라미터의 이름·형식 (구현 시 OpenAPI로 확정)
