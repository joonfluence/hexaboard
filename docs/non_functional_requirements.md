# 비기능 요구사항

성능, 비용, 보안, 무결성 등 품질 요구를 정리한다. 확정된 것만 적고, 정해지지 않은 것은 "미정"으로 표시한다.

## 요약

|----|------|------|------|
| NFR-01 | 성능 | 유휴 후 첫 로딩 지연 허용 | 확정 |
| NFR-02 | 비용 | 무료 플랜 범위에서 운영 | 확정 |

| NFR-05 | 무결성 | DB 스키마 변경은 마이그레이션으로 관리 | 확정 |

## 상세

### NFR-01 성능

- 서버(Render 무료 플랜)가 유휴 후 잠들었다가 깨어나는 동안 첫 요청이 최대 약 1분 걸릴 수 있으며, 이를 허용한다.
- DB(Neon)도 5분 유휴 후 잠들어 첫 로딩이 더 느릴 수 있다.
- 미정: 평상시 응답 시간 목표

### NFR-02 비용

- 무료 플랜으로 운영한다: Vercel(웹), Render 무료(서버), Neon(DB), GitHub Actions(공개 저장소).
- 각 플랫폼의 무료 한도와 조건은 자주 바뀌므로 구현 전 공식 문서로 재확인한다.

### NFR-03 보안: 비밀값 관리

- 저장소가 공개(public)이므로 DB 연결 문자열 등 비밀값은 커밋하지 않는다.
- 비밀값은 GitHub / Vercel / Render의 환경변수·시크릿으로만 관리하고, 로컬 `.env`는 `.gitignore`에 둔다.

### NFR-04 보안: 접근 통제

- 인증이 없고 저장소·배포 URL이 공개이므로 URL을 아는 누구나 티켓을 읽고 바꿀 수 있다.
- 이 위험은 **수용**한다. 향후 고도화하면서 인증을 추가할 때 해소한다. ([PRD 2차 제외 범위](PRD.md#3-2차-제외-범위))
- 브라우저가 서버를 직접 호출하므로 서버에 CORS 설정이 필요하다.

### NFR-05 무결성

- 스키마 변경은 마이그레이션 파일로 관리하며 필수 조건이다.
- 마이그레이션은 서버 기동 시 자동으로 실행한다. ([TRD 배포 전략](trd/06-deployment.md))
- 순서 키(`position`)는 바이너리 정렬 규칙(`C` collation)이 필요하다. ([data_model.md](data_model.md))
- 마이그레이션이 실패하면 기동을 중단하고, 복구는 수동으로 한다.

### NFR-06 유지보수성

- `domain`은 프레임워크를 모른다. `application`은 Nest 데코레이터를 허용한다.
- 의존 방향은 `package.json`의 `dependencies`로 강제해 위반이 빌드·설치 단계에서 드러나게 한다. ([TRD 계층 간 경계 규칙](trd/04-layer-boundaries.md))

### NFR-07 계약 일관성

- 서버 DTO에서 OpenAPI 스펙을 생성하고, 이를 기반으로 클라이언트 타입을 생성한다. ([api_spec.md](api_spec.md))
- 생성은 수동 명령으로 하고 생성물을 커밋한다. CI에서 생성 후 diff를 검사해 어긋남을 잡는다 (CI 구성 시점에 함께 넣는다).

### NFR-08 품질

- 자동화 테스트와 CI는 best-effort다. 미완이어도 MVP 완료로 인정한다.
- 백엔드 테스트 범위: `domain` 단위, `persistence` 통합(실제 Postgres), API/컨트롤러.
- `main`, `development` 브랜치로 PR을 올리면 GitHub Actions가 테스트를 실행한다.
- 프론트엔드 테스트 범위: 순수 로직 단위 테스트 + 컴포넌트 테스트(Testing Library). E2E는 하지 않는다.
- 미정: 드래그(dnd-kit) 상호작용을 컴포넌트 테스트에서 어떻게 다룰지

### NFR-09 접근성

- 드래그 앤 드롭은 dnd-kit을 쓴다. 키보드 조작 지원 범위는 구현 시 공식 문서로 확인한다.

### NFR-10 개발환경

- 테스트용 DB를 Testcontainers로 띄우므로 로컬과 CI 러너 모두 Docker 실행이 필요하다. ([TRD 개발환경 설정](trd/05-dev-environment.md))
