# 기능 요구사항

모든 기능은 MVP 필수(P0)다. 아직 정해지지 않은 세부는 [open_questions.md](open_questions.md)에 남기고, 여기에는 확정된 것만 적는다.

## 핵심 기능 목록

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| FR-01 | 티켓 CRUD | 티켓 생성/조회/수정/삭제 | P0 |
| FR-02 | 상태 관리 | `TODO` / `IN_PROGRESS` / `DONE` 상태, 전이는 자유 | P0 |
| FR-03 | 상태별 보드 화면 | 상태별 3개 컬럼에 카드로 표시 | P0 |
| FR-04 | 카드 이동 | 드래그로 상태 변경과 컬럼 안 순서 지정 | P0 |
| FR-05 | 마감일 | 티켓에 마감 날짜+시간 지정 (선택) | P0 |
| FR-06 | 우선순위 | 4단계 중요도 (필수) | P0 |
| FR-07 | 태그 | 자유 입력 태그를 여러 개 부착 | P0 |
| FR-08 | 검색/필터 | 티켓을 검색하거나 조건별로 필터링 | P0 |
| FR-09 | 정렬 | 기준을 골라 실행하면 카드 순서를 다시 저장 | P0 |

## 상세

### FR-01 티켓 CRUD

- 제목은 필수이며 도메인의 Title 값 객체가 검증한다.
- 설명(description)은 선택이다.
- 티켓의 공개 식별자 `ticketId`는 도메인에서 생성한 UUID다. DB PK와는 별개의 유니크 키다. ([data_model.md](data_model.md))
- 제목은 최대 100자, 설명은 최대 2000자다.
- 새로 만든 티켓은 `TODO` 컬럼의 맨 뒤에 놓인다.
- 생성은 컬럼 하단의 인라인 입력(제목만)으로 하고, 나머지 필드는 카드 상세 모달에서 편집한다. ([wireframe.md](wireframe.md))

### FR-02 상태 관리

- 상태는 `TODO` / `IN_PROGRESS` / `DONE` 세 가지다.
- 티켓 생성 시 상태는 항상 `TODO`로 시작한다.
- 상태 간 전이는 자유다. 어떤 상태에서든 어떤 상태로든 바꿀 수 있고, 도메인 불변식이 없다.

### FR-03 상태별 보드 화면

- 상태마다 컬럼 하나를 두어 총 3개 컬럼을 보여준다.
- 전체 UI와 디자인은 Trello를 참조한다. Trello와 달리 컬럼은 사용자 정의가 아니라 상태 3개로 고정이다.
- 화면 구성은 [wireframe.md](wireframe.md)를 본다.

### FR-04 카드 이동

- 카드를 다른 컬럼으로 옮기면 상태가 바뀐다.
- 같은 컬럼 안에서는 사용자가 드래그로 순서를 직접 지정한다 (수동 순서).
- 이동 요청은 "이 카드를 기준 카드의 앞/뒤로" 형태로 보내고, 서버(`domain`의 Position 값 객체)가 순서 키를 계산한다. 클라이언트가 계산한 값은 받지 않는다.
- 프론트엔드는 낙관적 업데이트로 배열 순서를 먼저 바꾼다.
- 순서는 같은 컬럼 안에서만 비교한다. 다른 컬럼으로 옮기면 대상 컬럼의 이웃 카드를 기준으로 새 순서를 정한다.
- 동시 이동으로 순서 키가 충돌하면 서버가 최대 3번 재시도하고, 계속 실패하면 `409`를 돌려준다. ([api_spec.md](api_spec.md))
- 이동이 실패하면(`409`, 네트워크 오류 등) 프론트는 낙관적으로 옮긴 카드를 원위치로 되돌리고 토스트로 알린 뒤, 서버 상태로 목록을 재조회해 맞춘다. 프론트는 자동 재시도하지 않는다 (서버가 이미 재시도함).

### FR-05 마감일

- 날짜와 시간을 함께 저장한다 (timestamp, UTC 저장, 표시할 때 변환).
- 비워둘 수 있다.
- 마감일이 없는 티켓은 마감일순 정렬에서 방향과 무관하게 항상 맨 뒤에 둔다. ([FR-09](#fr-09-정렬))
- 미정: 표시 방식

### FR-06 우선순위

- 값은 `LOW` / `MEDIUM` / `HIGH` / `URGENT` 네 단계다.
- 저장되는 값은 항상 있으며 기본값은 `MEDIUM`이다. 생성 요청에서 생략하면 기본값을 적용하고, `null`로 비울 수는 없다.
- DB에는 숫자로 저장하고, 도메인과 API는 문자열 enum을 쓴다. 변환은 매퍼가 맡는다.

### FR-07 태그

- 사용자가 자유롭게 입력한 태그를 티켓 하나에 여러 개 붙일 수 있다. 티켓과 태그는 N:M 관계다.
- 미리 정의한 카테고리는 이번 MVP에 없다.
- 태그 이름은 앞뒤 공백을 제거하고 소문자로 정규화하며 (`Docs`와 `docs`는 같은 태그), 이름은 유니크하다.
- 태그 이름은 최대 30자, 티켓당 최대 10개다.

### FR-08 검색/필터

- 티켓을 검색하거나 조건별로 걸러 볼 수 있다.
- 보드 상단 바에서 제공한다.
- 서로 다른 종류의 조건은 AND로 결합한다.
- 검색어는 제목과 설명에서 부분 일치로 찾는다.
- 태그를 여러 개 고르면 하나라도 가진 티켓을 보여준다 (OR).
- 필터 조건은 검색어, 우선순위, 태그다. 마감일 조건 필터는 제공하지 않는다 (마감일은 배지와 정렬로 다룬다).
- 필터는 서버 쿼리 파라미터로 실행한다. ([api_spec.md](api_spec.md))

### FR-09 정렬

- 정렬 기준을 골라 실행하면 `position`을 다시 계산해 저장한다 (순서 덮어쓰기 방식).
- 보기 전용 모드는 채택하지 않았다. 정렬을 실행하면 이전의 수동 순서는 덮어써진다.
- 정렬은 지정한 상태 컬럼 안에서만 실행한다 (컬럼 단위).
- 정렬 기준은 우선순위와 마감일이고, 오름/내림 방향은 실행할 때 지정한다.
- 마감일이 없는 티켓은 마감일순 정렬에서 방향과 무관하게 항상 맨 뒤에 둔다.
- 실행 취소(undo)는 제공하지 않는다.
- 필터가 적용된 동안에는 정렬 메뉴를 비활성화한다. 숨겨진 카드의 순서를 건드리지 않기 위해서다. 정렬 API는 항상 컬럼 전체를 대상으로 한다.
