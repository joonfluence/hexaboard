# 테스트 케이스

프로젝트의 테스트 케이스(TC) 정본이다. 무엇을 검증하는지(시나리오·기대 결과·근거)를 정의하고, 구현 상태를 표시한다. 기능 명세의 계약 케이스는 [contracts](../specs/001-ticket-create-get/contracts/tickets-api.md), UI 컴포넌트는 [component_spec.md](component_spec.md)와 짝을 이룬다.

## 상태

- ✅ 완료: 구현되어 테스트가 통과한다. ✅ (가정): 통과하지만 사용자 확인 전 가정에 기댄 케이스다.
- ⏳ 예정: 케이스는 정의됐고 아직 구현하지 않았다.

## 운영 규칙 (TDD와 연결)

1. 테스트를 쓰기 전에(RED 태스크 이전) 해당 TC를 정의한다: 시나리오, 기대 결과, 근거(FR·결정 번호). 상태는 ⏳다.
2. 테스트 이름에 TC ID를 넣는다 (예: `TC-API-014: 존재하는 ticketId를 조회하면 200`).
3. 테스트가 통과하는 GREEN 커밋에서 상태를 ✅로 바꾼다.
4. 문서에 없는 규칙을 가정하면 근거에 "가정"이라고 적고 상태를 ✅ (가정)으로 두며, 확정되면 `decision_log.md`에 기록한다.
5. TC를 정의하는 시점 이전에 만든 테스트(아래 ✅ 케이스)는 이름을 바꾸지 않고, 각 문서의 파일 경로와 시나리오로 대응시킨다. 이 사후 정의는 [changelog.md](changelog.md) v0.81에 기록했다.
6. 한 TC가 매개변수 여러 개(`it.each`)의 테스트를 포함할 수 있다.
